# modal-root: behaviour contract

Each line is one browser test in `tests/contracts/modal-root.contract.test.tsx`, named by its id. `src/lib/behavior/modal-root.tsx` holds `ModalRoot`, its context (`useDialogContext`), `ModalTrigger`, `ModalTitle`, `ModalDescription` and `ModalFrame`: the owned modal the Dialog family skins. It assembles controllable, polymorphic, layer stack, dismiss, presence, focus scope and hide outside; every block keys on `isOpen()`. With `keep`, a closed layer stays mounted and dormant: Presence keeps it, and the layer root (the portal's container) carries `data-dormant`, which skips its content. The rows run through the public `Dialog` API, so they hold the skin and the root together.

| id | when | then |
|---|---|---|
| MR1 | a panel with a `DialogTitle`, a `DialogDescription` and `ariaLabel`; then one with only `ariaLabel` | the Title names the panel and `aria-label` is absent; the Description describes it; the untitled panel is named by `ariaLabel` and has no `aria-labelledby` |
| MR2 | the trigger, closed, then pressed | `aria-haspopup="dialog"` and `aria-expanded="false"` with no `aria-controls`; open, `aria-expanded="true"` and `aria-controls` names the panel's id |
| MR3 | `defaultOpen`, Done pressed, the trigger pressed | starts open, closes, reopens; `onOpenChange` reports `[false, true]` |
| MR4 | `onEscapeKeyDown` and `onInteractOutside` call `preventDefault`; Escape, then a press beside the panel | the dialog stays open |
| MR5 | `ref`, `data-testid` and `onKeyDown` on the content | `ref` receives the panel; the attribute and the handler reach it |
| MR6 | the dialog inside a closed shadow root; then on the page | in the shadow root nothing on the page gets `aria-hidden`; on the page what is beside it gets `aria-hidden="true"` |
| MR7 | a Select list opened inside the dialog, then the dialog closes | the list closes with it: every layer whose trigger or element sits inside the panel is dismissed, newest first |
| MR8 | a `modal` Popover open; a Dialog opened from a button inside it, Confirm pressed, then Keep | the panel sits under no `aria-hidden`, holds focus and takes the press; Keep closes the dialog and the popover stays open: a Kobalte root drops `modal` while an owned modal covers it, and the owned modal's portal takes pointer events whatever the body says |
| MR9 | a Dialog open on the page; one with `modal={false}`; one inside a closed shadow root | the modal panel carries `aria-modal="true"`; the non-modal panel and the shadow-root panel carry no `aria-modal` |
| MR10 | a `Toaster` beside a modal Dialog that is open, then `toast("Scene saved")` | the panel carries `aria-modal="true"` and the toast's text is in the Chromium AX tree |
| MR11 | a `data-kb-top-layer` "Wake screen" button on the page, then a modal Dialog opened | the panel carries `aria-modal="true"` and `button "Wake screen"` stays in the Chromium AX tree |
| MR12 | a controlled modal with no Trigger closes; `onCloseAutoFocus` calls `preventDefault` and focuses an unmarked page button | focus ends on that button after the exit: the trap lets go before the consumer runs |
| MR13 | `onPointerDownOutside` and `onInteractOutside` on the content, a press on the scrim | both receive the same cancelable `CustomEvent`, pointer handler first; its `target` and `detail.originalEvent.target` are the scrim, `detail.originalEvent` is the `PointerEvent`, `detail.isContextMenu` is false (Kobalte's shape) |
| MR14 | `onEscapeKeyDown` on the content, Escape with a button inside focused | the handler receives the trusted keydown itself, whose target is that button |
| MR15 | a modal Dialog; a right-button press on the scrim, then a Ctrl+primary press, then a plain press | the first two report `isContextMenu` true and the modal stays open (Kobalte's DialogContent cancelled a modal's context-menu press); the plain press closes it |
| MR16 | focus on a `data-kb-top-layer` button outside an open modal, Escape; then two stacked modals, Escape twice from that button | the modal closes (the topmost modal reads Escape from the document, as Kobalte did); of the two, the first Escape closes only the top one and the second the lower |
| MR17 | two stacked modals, focus inside the top one, whose `onEscapeKeyDown` prevents; Escape, then the veto lifted and Escape | the first Escape closes nothing; the second closes only the top one |
| MR18 | a `ModalFrame` with no motion, `exitMs` 100 while open, changed to 400, then closed | the panel is still mounted 200 ms after the close and gone by 400 ms: the exit reads the duration current when it closes (an anchored Dialog's 150 ms, a centred one's 120 ms) |
| DK1 | a kept Dialog, open with its page cover, closed until its exit ends | the attributes written as it goes dormant are `data-dormant` on the layer root (the portal's container), the panel's `role` and `aria-modal` (DK3) and its `data-covering` (DK4); nothing gets `inert`, `hidden`, `style` or `class`; the root's `position`, `contain` and `z-index` read the same shown and dormant |
| DK2 | a kept Dialog dormant, in Chromium and WebKit (`modal-root-dormant`), and in Chromium's AX tree | its button takes no focus by `focus()` or by Tab, `elementFromPoint` at the button finds nothing in the layer, `window.find` misses its text, and the AX tree has neither its title nor its button; open, each of these reaches it |
| DK3 | a kept Dialog dormant, then reopened | the dormant panel carries no `role` and no `aria-modal`; reopened, `role="dialog"` and `aria-modal="true"` return |
| DK4 | a kept Dialog dormant under an open modal; Escape; the modal again and a press beside; the kept one reopened and closed | dormant, it holds no layer, hides nothing on the page, keeps no edge stops and leaves the page uncovered; Escape and the press close only the open modal; reopened, focus lands where the first open put it and the page is covered again; closed, focus returns to its trigger |
| DK5 | a kept anchored Dialog, its anchor moved while dormant, reopened | the panel is placed over the anchor's new box |
| DK6 | a centred and an anchored Dialog, at the `animationend` of their exits | the panel and the scrim compute `opacity: 0`: an exit rests closed instead of snapping back |
| DK7 | a kept Dialog, and a kept `ResponsiveDialog`, reopened with nothing changed | the same panel and scrim nodes, and no node added inside them: only the focus trap's two edge stops beside the panel. The style and layout half is the `keep-reopen` and `keep-changed` budgets |
| DK8 | a kept Dialog with a Select list open inside it, closed | the list closes with it, and the layer stack is empty while the Dialog is dormant |
| DK9 | content reading `useDialogContext().dormant` | true while mounted closed, false while open and closing, true once the exit ends, false again on reopen |
